# Changelog

## 2026.10.20.1 — Fetch guard

- **A timed-out background fetch no longer fills the disk** (infra-vps VH-T20: `git fetch` killed at 15 s left an orphan `.git/objects/pack/tmp_pack_*` per 15-minute run, 17 GB in ~4 h). New `scripts/fetch_guard.py`, used by `repo_sync.sync` and both `auto_return.py` fetches: on timeout git's whole process group is killed (`session_sync.git` now runs git in its own session; `info["timeout"]`), only the `tmp_pack_*`/`tmp_idx_*` files created during that run are deleted, and consecutive timeouts are counted in `<git-dir>/epicspine-backoff.json`. From the 2nd strike the repo is skipped for 30 min, doubling to 6 h, with an `EpicSpine attention:` line naming the path for a manual `git fetch origin`; a successful fetch resets it. A longer retry budget was not added (the per-repo clock is 20 s). Tests: `FetchTimeoutTest`. Skill 2026.10.20.1.

## 2026.10.19.3 — Living tree

- **Agents keep the epic log true.** Always-on rule 6 (`global-block.md`): every new ask is placed in the tree before work starts (the reply states `Goal: EPIC-<n>`, an open goal from `spines.py --active` or a new spine from `spine_new.py`); a done goal closes (`Status: done`, parent rolls up); a replaced one gets `Superseded by:`; stale goals flagged at SessionStart are reported, never closed silently.
- **`spine_new.py` assigns the code**: title `# EPIC-<n>: <title>`, n = highest code among the repo's goal titles (legacy `E4`/`EPIC 0` counted) + 1, never 0 (the root is EPIC-0); `--code N` overrides; DoD IDs `E<n>-`; the parent's (or AGENTS.md) `Integration policy:` is copied.
- **`spines.py`**: `--active` lists open goals; node JSON gains `superseded_by`, top level gains `stale: [{path, title, days}]` (active/blocked, file's last commit 14+ days old). New helper `epic_log.py` holds rollup, the text views, code and stale logic (spines.py 200 -> under 170 lines).
- **Gates**: pre-commit blocks a `Superseded by:` link that is no goal doc and warns (never blocks) when a goal's Current State exceeds 12 lines. The 15-minute background sync (`background_sync.py`, never SessionStart, which stays scan-free) records one stale-goals line per repo with a root spine; SessionStart prints it, for the current repo too. Tests: `tests/test_living_tree.py`. Skill 2026.10.19.3.

## 2026.10.19.2 — Epic log wording

- **Spines are nested markdowns; leaf-vs-DoD-line is judgment.** Progress within a goal goes in that goal's spine; a new measurable objective worked over iterative pushes (sprint/plan) gets a leaf markdown linked from its parent, a small one-push item stays a DoD line. Every goal is `EPIC-<n>: <short name>`, with a one-line goal and measurable success criteria. **Status words**: `Status:` is the only status source (`Waiting on:` is context, never blocked); `ready` = defined, not started, launching a persona makes it `active`; `deferred` = paused by the user; `blocked` = a named external dependency. SKILL.md Epic Log, `references/spine-model.md`.
- **Manifest skips `__pycache__` and `*.pyc`** (`tools/epicspine-manifest.sh`, `skill_update.generate_manifest`): a working tree with bytecode no longer produces lines that CI's clean checkout rejects. `test_manifest_excludes_pycache`. Skill 2026.10.19.2.

## 2026.10.19.1 — Epic log

- **"On latest EpicSpine" means installed and docs conform.** The skill version, hooks and AGENTS.md block were never the whole story: nothing created, checked or listed the goal documents themselves (poly-maker E4 was a plain ticket-table doc, invisible to the console picker; `docs/handoffs/2026-10-19-spine-conformance.md`). A repo now has one **epic log**: a tree of goals hung from the root spine (the trunk, which states the purpose). A goal is a node under the root or another goal; it gets its own spine file when it has its own DoD, children or spans sessions, otherwise it is a `- [ ] <ID> text` DoD line in its parent. The child's `Parent spine:` header decides its place, the parent's Spine Map must agree (checked, not trusted), parent state rolls up from children. Files and header fields keep their names. SKILL.md (Epic Log section), `references/spine-model.md` (definition + the discovery JSON schema), `references/spine-creation.md`.
- **`scripts/spine_new.py --repo DIR --parent SPINE --path FILE --title T [--purpose P]`** scaffolds a valid v1 compact goal spine (Spine Type `branch`, the validator's word for a non-root spine; Root/Parent spine links; `Status: draft`; checkbox DoD; Issue Ledger) and registers its Spine Map row in the parent (section created when missing). Parent by path or Spine ID. Idempotent, never overwrites; output passes `--trackable` and `--strict --graph`.
- **`scripts/spines.py [--json] --repo DIR`** discovers the tree: root from AGENTS.md `Root spine:` (else a root-typed header), children by Spine Map and `Parent spine:` header, DoD checkboxes as leaves, derived `rollup_status`, `orphans` (goal docs outside the tree: any `Spine ID:` file or `E<n>-*`/`EPIC*`/`*SPINE*`/`*PLAN*` name, minus `archive/`, `node_modules`, dot-dirs, `handoffs/`, `examples/`, `fixtures/`, `test/`, `tests/`, vendored skills) and `mismatches` (header vs map, map row to a missing file). `Root spine: none` gives root null, exit 0. The agent_team console picker consumes this.
- **Pre-commit gate** (`pre_commit.py`): a newly added or renamed goal doc, or a modified one whose HEAD version already had `Spine ID:` (migrated), without a valid v1 header, outside the tree (parent chain does not reach the root) or disagreeing with its parent's Spine Map is blocked with a one-line fix naming `spine_new.py`. Rollout-safe: a modified legacy goal doc (no `Spine ID:` at HEAD), a root spine without a `Spine ID:` header ("migrate the root first") and `Root spine: none` only warn, so unmigrated repos keep working until their migration. `--trackable` + tree only; `--strict` stays advisory. Only the staged file and its parent chain are read. `tests/test_epic_log.py`; two `PreCommitHookTests` in `test_trackable.py` now use `Root spine: none` since their `Spine ID` fixture is deliberately parentless. Skill 2026.10.19.1.
- **Fixes after review.** `Parent spine:` and Spine Map links resolve against the file's folder, else the repo root (agent_team writes `Parent spine: docs/spines/root.md`; its children were all orphans). `test/` and `tests/` are skipped (agent_team's `console/server/test/real/*.md` fixtures were orphans).

## 2026.10.16.13 — Deploy gate in auto-merge

- **Closes the gap noted in .12: the background auto-merge now honours `Deploy gate:`.** A deploy-gated path rolls a production deployment, so it must go through PR/CI, never `scripts/auto_return.py`. New `scripts/deploy_gate.py` (pure functions; `auto_return.py` only calls it) reads the whole `Deploy gate:` line (`repo_sync.field` keeps only the first token) from every occurrence in AGENTS.md and the root spine. Entries are repo-relative path prefixes or globs (`*`, `?`, `**`; an entry without `/` matches that name at any depth; case-insensitive, so it errs towards blocking). (1) A branch touching any gate entry, by any change type including edits/deletes/renames, is not merged and is reported `<branch> (touches Deploy gate <entry>)` in the "marked Ready but not auto-merged" line. (2) A gate value that is not only paths/globs (a branch name, prose, a URL, `..`, an absolute path, braces) blocks auto-merge for the whole repo: `auto-merge is blocked for this repo: the Deploy gate value (...) is not only paths or globs`; `none`, `n/a`, `-` or empty declare no gate. (3) An `Integration policy:` text mentioning a PR or CI (zenod: "main-direct via self-merged CI-gated PR") blocks auto-merge entirely, reason `its Integration policy mentions a PR/CI gate`. Already-merged branch cleanup is unchanged. `references/git-doctrine.md`, `references/session-sync.md`, SKILL.md and Book deck file lists; `tests/test_deploy_gate.py` (gated path blocked, ungated additive still merges, spine-declared gate, unparseable gate blocks the repo, PR-mentioning policy blocks, matching and parsing). `auto_return.py` budget 200 -> 206 (see `tests/test_budgets.py`). Skill 2026.10.16.13.

## 2026.10.16.12 — Deploy exception

## 2026.10.16.11 — Return to main

- **Everything in main; worktrees only for substantial work.** After the 2026-10-16 VPS cleanup (`docs/hygiene/2026-10-16-cleanup.md`): purely additive, no-risk work (new docs, research, shortlists, files) commits and pushes straight to main; work editing existing code/config uses `wt/<task>`, merged as soon as each step passes (ff or `--no-ff`, never squash) and removed right after. No branch outlives its task (unmergeable work is pushed and reported with a one-line reason; follow-ups go on a NEW branch). A finished branch carries the commit trailer `Ready: yes`; nothing without it is merged automatically. Repos declare `Integration policy:` (new setups main-direct) and, if they deploy, `Deployed from:`. Global block rules 2, 4, 5 and the Sync line, SKILL.md rules 3/4/7, `git-doctrine.md`, `roles-and-dispatch.md`, `role-protocols.md`, the dispatch preamble. GitHub repos: `delete branch on merge`, merge commit / rebase, not squash.
- **Soft escalation, never forced.** Un-ready branches: nothing under 3 days, an attention line from 3 days, at 14 days ask the user once: keep / park (remote kept, local worktree and branch removed) / drop (annotated tag `archive/<name>` pushed and verified first; never delete without it unless the branch is in main).
- **Cleanup safety checklist** in `references/hygiene.md`: a MERGED PR does not prove the branch is in main (compare `headRefOid`, check the base; commits pushed after a squash merge are lost); `gh pr list` truncates (use `--head`); deployed code may run from containers or root-owned checkouts (`Deployed from:`, running processes); `fetch --prune` before every delete; cron-written tracked files must not stay dirty in a primary checkout.
- **Auto-return to main** (`scripts/auto_return.py`, from `local_mess.guard`): in `Integration policy: main-direct` repos (off: `EPICSPINE_AUTOMERGE=off` / `Auto-merge: off`) a branch whose tip has `Ready: yes`, whose diff only adds files (nothing under `.github/` or named `.git*`), that merges cleanly (`git merge-tree --write-tree`), has no open PR (`gh`; unavailable means no merge), is >= 2 h old and whose worktree is clean with no process inside is merged `--no-ff` in a temporary worktree, pushed ff-only (rejected: stop and report), then branch and worktree removed. Branches already in main are deleted locally (origin only `wt/*`; others reported). Everything else is reported with the 3 d / 14 d wording.
- **State, cap, table** (`scripts/repo_state.py`): SessionStart prints `EpicSpine state: <repo> main clean|dirty(N), in sync|ahead N|behind N · worktrees N · branches not in main N` and, above 3 open worktrees, `EpicSpine attention: <repo>: N open worktrees (cap 3) — finish or merge one before starting another`; `python3 scripts/repo_state.py` prints one row per repo from the status file.
- **Vendored-copy tolerance:** a copy is flagged only when its VERSION date is more than 7 days older than the installed skill's (zenod's pinned `.9` is no longer flagged against `.10`).
- Local-mess budget 25 s -> 40 s per repo; `references/hygiene.md` and `git-doctrine.md` budgets raised with reasons in `tests/test_budgets.py`. Skill 2026.10.16.11.
