## Lessons (now in the skill)

- Everything lives in main; a worktree is only for work that touches something substantial. Purely additive, no-risk work (new docs, research, shortlists, new files) commits and pushes straight to main.
- No branch outlives its task: merge when each step passes (ff or `--no-ff`, never squash, history travels) and remove branch and worktree right away. If it cannot merge, push it and say why in one line. Follow-ups go on a new branch, never on a merged one.
- A branch is marked finished with the commit trailer `Ready: yes`. The background job merges only marked, purely additive, conflict-free, PR-free branches in `main-direct` repos; everything else gets soft reminders (3 days, then ask once at 14 days: keep / park / drop). Nothing is forced.
- A merged PR does not prove the branch is in main: compare the PR's `headRefOid` with the branch tip (commits pushed after a squash merge are lost) and check the PR base is main (stacked PRs merge into other branches).
- `gh pr list` truncates: query per branch with `--head`.
- Deployed code can run from containers or root-owned checkouts: repos declare `Deployed from:` and agents check running processes before touching anything.
- `git fetch --prune` again before every delete: concurrent workers move main.
- Never delete an unmerged branch without first pushing and verifying an annotated `archive/<name>` tag.
- Files written by cron or timers must not be tracked and dirty in a primary checkout: commit them from the job or gitignore them.
- On GitHub set `delete branch on merge` and allow merge commit / rebase, not squash.
